# AGENTS.md — edu-lab

> Tool-agnostic guide for AI agents **and** humans. A **no-build static** worksheet
> generator (printable K–5 worksheets) published to `edulab.appalachiancloud.co`.
> Read this, then `README.md` + `DEPLOY.md`, then `~/Code/AGENTS.md` (workspace map).

## Stack & publish
- **Site:** plain HTML/CSS/JS, no build step (`index.html`, `app.js`, `banks.js`, `generator.js`, `stem.*`, `themes.*`, `support.js`, `wizard.js`, `styles.css`; plus `contact.html` + `contact.js` — a standalone Turnstile-protected contact page, see gotchas). CI syntax-checks JS with `node --check`. **Script load order** in `index.html` is dependency-ordered: `banks.js` → `generator.js` → `themes.js` → `stem.js` → `support.js` → `app.js` → **`wizard.js` (last)**. `wizard.js` is the optional, skippable onboarding modal — it builds its own DOM, drives the existing sidebar controls, and **reuses `app.js`'s generate path** (it fires `change` on `#subject`/`#type` rather than duplicating generation), so it MUST load after `app.js` has wired its listeners. It is a pure progressive enhancement (the generator works fully if `wizard.js` is skipped or fails to load) and is marked `no-print`. The "seen" flag is `localStorage['lah_wizard_seen']` (local-only, honors the no-account/no-tracking promise). `support.js` is a data-driven support-link footer — its `SUPPORT_LINKS` array currently ships **empty** (no public support page yet; re-enable criteria are in the file). **Display brand is "LessonsAtHome" (an Appalachian Cloud project); repo/infra keep the `edu-lab`/`edulab` identifiers.** Brand spec + tokens: `BRAND.md` + `styles.css :root` (single source of truth).
- **Infra:** `terraform/` — S3 (AES256) + CloudFront (OAC) + ACM (DNS-validated). Apply with **`aws-vault exec edulab-terraform`** (region us-east-1, MFA). The account baseline + `appalachiancloud-edulab-terraform` role already exist.
- **Deploy:** merge to `main` → GitHub Actions → OIDC (`appalachiancloud-edulab-github-deploy`) → S3 sync → CloudFront invalidation. Requires repo **variables** `AWS_ACCOUNT_ID`, `S3_BUCKET`, `CLOUDFRONT_ID` (from `terraform output`; see `DEPLOY.md`).

## ⚠️ Open items / gotchas
- **Contact page (`contact.html` + `contact.js`) reuses the mountain-infra ACE contact relay — three cross-repo couplings.** (1) The POST endpoint (`https://bep3iwibed.execute-api.us-east-1.amazonaws.com/contact`) is Terraform-generated in `mountain-infra/terraform/lightsail/contact_api.tf`; if that API is recreated, update `contact.js` **and** the CSP `connect-src` in `terraform/main.tf` together. (2) CORS: the relay must list `https://edulab.appalachiancloud.co` in `var.contact_allowed_origins` (mountain-infra). (3) The Turnstile site key in `contact.html` is the **ACE widget's** public key (a root-domain widget hostname covers subdomains) — it must stay paired with the secret the Lambda reads from SSM. The CSP's only third-party allowances exist for this page: `script-src`/`frame-src challenges.cloudflare.com` + `connect-src` the relay origin. No email address or `mailto:` may appear anywhere on the site — the inbox lives server-side in the relay.
- **Not every subject has a worksheet type at every grade — the wizard must not steer users into an empty combo.** `TYPE_META`/`STEM_META` gate types by grade: **Reading** starts at Grade 1 (no Kindergarten), **Language Arts** starts at Grade 2 (no K/G1); **Math** and **STEM** cover all of K–5. If a subject+grade pair has zero types, `app.js populateTypes()` yields an empty `#type` and `generate()` bails early (`if(!opt.type) return;`) — the sheet silently goes stale. `wizard.js` guards this by computing valid subjects per grade **from the live `window.WS.TYPE_META`** (data-driven, so it can't drift from the generators) and disabling/​swapping-away invalid subject options with a friendly note. **If you add a subject or change a type's `grades`, no wizard change is needed** (it reads TYPE_META), but keep the recipe presets in `wizard.js RECIPES` pointed at valid combos.
- **Live (2026-07-04):** `https://edulab.appalachiancloud.co/` serves HTTP/2 200 via CloudFront `E30K4N661AMPGX` on ACM cert `fc790fc9-b282-4b22-a93a-ccdb405c82e4` (Amazon RSA 2048, valid to 2027-01-17). TLS 1.2+ only. Origin S3 bucket `appalachiancloud-edulab-site` is public-access-blocked and OAC-locked. Baseline security headers (HSTS 1y+includeSubDomains, XFO SAMEORIGIN, XCTO nosniff, Referrer-Policy strict-origin-when-cross-origin, XSS-Protection, CSP) applied via `aws_cloudfront_response_headers_policy.site`. Deploys via GitHub Actions OIDC (`appalachiancloud-edulab-github-deploy`) on push to `main`.
- **Domain:** `edulab.appalachiancloud.co` (`.co`, not `.com`). `.co` is the primary ACE zone; `.com` is redirect-only. `README.md`, `DEPLOY.md`, and `terraform/variables.tf` are consistent.
- **Brand tokens are single-sourced in `styles.css :root` (see `BRAND.md`), but a recolor is only partial if you stop there.** Hardcoded colors also live **outside** `:root`: `styles.css` word-search hit (`.wsgrid td.wshit`), `themes.css` `var(--accent, …)` fallbacks, `app.js` inline-SVG fills (fraction bars, geometry, clock hand), and the **inline SVG favicon** in `index.html`. Change all of them together, then gate on `grep -rn '2563eb\|1d4ed8\|f4f6fb\|eef2ff\|bfdbfe' --include=*.css --include=*.js --include=*.html .` returning nothing. **Decoration tokens `--sky`/`--sun` are never text** (they fail WCAG AA); text/UI uses `--accent` (`#1F6FA5`, AA-verified).
- **CI:** the build/deploy workflow (`ci.yml`) passes. **CodeQL is enabled and green** (advanced setup via the repo's own `codeql.yml`, weekly scheduled runs on `main`, 0 open alerts — verified 2026-08-12, issue #21 closed). Note GitHub's *default setup* toggle reads "not configured" — that's expected with advanced setup; don't flip it on (it would conflict with `codeql.yml`).
- **OIDC provider lookup uses `arn`, not `url`:** the scoped `appalachiancloud-edulab-terraform` role has `iam:GetOpenIDConnectProvider` but not `ListOpenIDConnectProviders`. The data source in `terraform/main.tf` is ARN-form so plan/apply work without a baseline change.
- Unlike Boss BOS, edu-lab uses **AES256** (not KMS) with no origin-request policy and no `aws:RequestedRegion` condition, so it does not need those fixes.
- **Asset caching / cache-busting (#16, fixed):** CSS/JS are uploaded `immutable, max-age=1yr` on **unversioned filenames**, so CloudFront's `/*` invalidation alone does *not* refresh **returning browsers**. The deploy fixes this by rewriting the HTML pages (`index.html` + `contact.html`, a loop in `ci.yml`'s "Sync static site to S3" step) at upload time to append `?v=<short-sha>` (`${GITHUB_SHA::8}`) to each local `.css`/`.js` ref; the HTML pages themselves stay `no-cache`. **Do not** reference CSS/JS from the HTML in a way the `sed` can't version (keep refs as bare local `name.css`/`name.js`), don't drop the versioning step — without it, CSS/JS changes are invisible to repeat visitors until hard-refresh — and **any new top-level `.html` page must be added to both the sync `--exclude` list and that loop**.
- **S3 sync is a whole-repo publish — the `--exclude` list is the ONLY thing keeping repo internals off the public site.** The "Sync static site to S3" step runs `aws s3 sync . s3://…`, so *anything* not excluded (or not caught by the trailing `index.html` special-case) is served at the site root. The exclude list must cover every tooling/internal directory — `.git/*`, `.github/*`, `.claude/*`, `terraform/*`, `tests/*`, `node_modules/*`, plus `*.md`/`LICENSE`/`.gitignore`. `.claude/*` was **missing** and briefly exposed `/.claude/settings.json` + `/.claude/hooks/guardrail.py`; adding it plus the existing `--delete` purges those objects on the next `main` deploy. **When you add a new top-level dir that shouldn't ship, add its `--exclude` in the same PR.**
- **⚠️ `enable_custom_domain` MUST stay `true` (fixed 2026-07-06):** this two-phase toggle gates the CloudFront custom cert + alias + `TLSv1.2_2021`. It now **defaults to `true`** — the launched steady state. It was previously `false`, and because there is **no committed `terraform.tfvars`**, every `terraform plan/apply` silently wanted to revert the live site to the default `*.cloudfront.net` cert + `TLSv1` + no alias (i.e. take HTTPS down on `edulab.appalachiancloud.co`). The launch had set it `true` only *transiently* (a `-var`), which never persisted. **Guardrail: never hold a persistent infra state in a transient `-var` or an un-committed tfvars — bake the steady state into the committed default.** Only flip to `false` for a genuine from-scratch re-bootstrap (ACM cert not yet Issued).

## 📝 Documentation & change discipline

Publication must stay **repeatable from the repo**. In the **same PR** as any change, update the docs it affects — the change isn't done until they are: this `AGENTS.md`, `README.md`/`DEPLOY.md`, the gotchas above (a failure + its fix), **TODO/follow-ups**, and `CHANGELOG.md`.

**Out-of-band changes → raise an issue.** Anything changed outside Terraform/Git — a hand-edited **SSM** parameter or an **SSH**/console change — is drift: open a GitHub issue (`mountain-infra` for server/SSM; this repo for the site/its infra) so it gets codified, and prefer changing code first. Never read `*.tfstate`, and never persist an SSM `SecureString` value to disk, PR body, commit message, log, or stdout. Reading/writing `*.tfvars` is allowed — real secrets live in SSM SecureStrings, so tfvars hold only non-sensitive config; if a real secret is ever found in a tfvars, treat it as a finding and move it to SSM. (The `Read(./**/*.tfvars)` deny in `.claude/settings.json` was **removed** on 2026-07-07, so agents may read/write tfvars directly; the `Read(./**/*.tfstate)` deny **stays** (state holds resolved secrets), and editing `.claude/settings.json` or `.claude/hooks/` remains **human-only**.) **Exception (human-approved, per invocation):** an AI agent MAY resolve an SSM `SecureString` into an ephemeral shell env var when the immediate consumer is a sanctioned tool that reads that env var (e.g. `CLOUDFLARE_API_TOKEN` for `terraform apply`); the read must happen inside the same shell command as the consumer, and the value must not be echoed or captured elsewhere.

See **`~/Code/AGENTS.md`** for the full workspace map + policy, and this repo's `.claude/settings.json` + `PreToolUse` hook for the enforced "do no harm" guardrails (work on branches, open PRs, treat `main` as protected).
